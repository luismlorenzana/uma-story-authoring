# CY63 Story authoring · Equipment identity, boss staging and signature actions

## Outcome and linked work

Keep tactical preparation, enemy identity and signature attacks coherent with the authored campaign.
Use the [delivery contract](delivery-contract.md), [CY57 Composition](https://github.com/luismlorenzana/uma-cyberpunk/blob/main/docs/handoff/tasks/CY57.md),
[CY58 Equipment](https://github.com/luismlorenzana/uma-cyberpunk/blob/main/docs/handoff/tasks/CY58.md), [CY59 Crew](https://github.com/luismlorenzana/uma-cyberpunk/blob/main/docs/handoff/tasks/CY59.md), [CY60 Enemies](https://github.com/luismlorenzana/uma-cyberpunk/blob/main/docs/handoff/tasks/CY60.md),
[CY61 Signatures](https://github.com/luismlorenzana/uma-cyberpunk/blob/main/docs/handoff/tasks/CY61.md) and [CY62 Attack Art](https://github.com/luismlorenzana/uma-cyberpunk/blob/main/docs/handoff/tasks/CY62.md). Begin the brief before bulk armor/weapon
and signature authoring. This packet does not rewrite the completed service plots as a new campaign.

## Equipment and combat cast

1. Map actual encounter units to their private identities, role, commander/sub-boss/support status,
   approved armor baseline and canonical equipment. Start with the first boarding group, then
   cover the actual Tier 1–5 ground registry. Reuse identities consistently across encounters.
2. State which weapon/part is standard issue, fitted with planetary resources or unique to an
   authored character. Distinguish player loadout choice from fixed lore. Give Art the visible
   meaning of important equipment without inventing new catalog items in dialogue.
3. Reconcile gear preparation, deployment, sealed/unsealed helmet staging and the same actor's
   post-battle custody/release. A larger boss needs a silhouette/scale brief. Literal creatures,
   transformations and multi-tile occupancy are explicit development requests with scene purpose.

## Signature brief and writing

4. With CY61, define the first recruit's signature intent and her actual opponent's warned signature.
   Return the action key, player-facing purpose, eligibility/unlock, weapon dependency and the
   intended counterplay. Development supplies numeric tuning and supported rules; unsupported
   effects remain requests until implemented.
5. Write concise selection/commit, boss warning, execution and cancellation/result lines as needed.
   Use exact actor and expression tags, CY62 splash/pose intent and the implemented cue format.
   Routine attacks remain short. Fast/skip retains the information needed to understand the result.
6. A signature introduction occurs in its real Training/prep/service mission context. Keep Training
   optional and recruitment independent. Do not make the Captain select romance to unlock a weapon
   or force a previously completed quest to replay. Specify an acknowledgement/fallback for a save
   that has already passed the introductory beat.
7. Expand to every eligible playable character and boss by tier. Shared mechanical action families
   can have character-specific names and lines. Record the exact family/action key so an evocative
   name does not imply extra mechanics. Name featured sub-bosses that need dedicated splashes.

## Handoff

Return checked private scripts and the cast/equipment/action matrix, occurrence and unlock rules,
saved effects, dialogue/cue IDs, warning/cancellation states and precise art references. Provide the
first short draft before CY61 implementation closes. Return an explicit list of new parser/rule
requests and a scoped revision list for combining the story export.

Check consistency between pre-battle outfit, weapon in the splash, actual rig, warned target/area,
result log and custody outcome. Enemy recovery stays nonlethal. The same likeness carries into
the boss-ally presentation; a cinematic does not change her disposition.

## Verification and completion

Play the actual funded prep and first hero/boss fight, optional Training, both entry routes,
signature cancellation, a saved warning, loss/free retry and a later-tier fight. Read lines with
their real art and skipped/fast playback. Run story/game pack checks against the supported format.

Done when the full combat registry has coherent equipment/cast mappings and every supported
signature has checked staging and cue text. Art and development can implement each row without
guessing its purpose, unlock or outcome. Record review/device findings and delete with a Done row.
